# KOTOBA MORI 🌱
### 생성형 AI 기반 어린이 일본어 학습 서비스

> 아이들이 놀고 콘텐츠를 즐기다 보면 자연스럽게 일본어를 익히는 서비스

KOTOBA MORI(코토바 모리)는 일본어 동요·애니메이션 콘텐츠, 그림과 발음을 활용한 단어 학습, 히라가나 연습, AI 캐릭터 회화, 게임형 보상 시스템을 결합한 어린이 대상 일본어 학습 서비스입니다.

어린이가 콘텐츠 속에서 새로운 단어를 발견하고, 직접 듣고 말하고 써 본 뒤, 학습 보상으로 자신만의 마을을 성장시키는 경험을 제공합니다. 학습 기록을 활용해 어려워하는 단어를 다시 연습하도록 함으로써 개인별 학습 경험을 지원하는 것을 목표로 합니다.

> **프로젝트 상태:** 기획 및 개발 예정  
> 아래의 기능과 기술 구성은 프로젝트 계획을 기준으로 작성했습니다. 실제 구현 여부에 맞춰 README를 업데이트합니다.

## 🎯 프로젝트 배경

어린이가 외국어를 학습할 때 단어와 문자를 반복해서 암기하는 방식은 지루하게 느껴질 수 있습니다. 또한 단어의 뜻을 아는 것과 실제 대화에서 표현을 사용하는 것 사이에는 차이가 있으며, 학습자마다 어려워하는 단어와 학습 속도도 다릅니다.

KOTOBA MORI는 이러한 문제를 해결하기 위해 **콘텐츠 기반 학습 + AI 상호작용 + 개인화 복습 + 게임화**를 하나의 경험으로 연결합니다.

### 해결하고자 하는 문제

- 일본어 문자와 단어를 처음 접하는 어린이에게 학습이 어렵고 지루하게 느껴질 수 있습니다.
- 단순 암기만으로는 배운 표현을 실제 대화에서 활용하기 어렵습니다.
- 모든 학습자에게 같은 콘텐츠를 제공하면 개인별 학습 차이를 반영하기 어렵습니다.
- 학습 성취를 체감하고 꾸준히 참여할 수 있도록 돕는 동기가 필요합니다.

## 🚀 프로젝트 목표

1. 동요와 애니메이션을 학습의 시작점으로 활용해 일본어에 대한 흥미를 유도합니다.
2. 이미지·발음·문자를 연결해 기초 일본어 단어를 학습하도록 돕습니다.
3. 히라가나 따라쓰기와 AI 캐릭터 대화를 통해 배운 내용을 직접 연습하도록 합니다.
4. 학습 기록을 바탕으로 복습이 필요한 단어와 개인화 미션을 제공합니다.
5. 포인트와 마을 성장 시스템으로 학습의 성취감과 지속적인 참여를 지원합니다.

### 핵심 타깃

- **주요 대상:** 만 6~8세 어린이
- **학습 수준:** 일본어 입문 및 초급
- **사용 환경:** PC·태블릿·모바일 웹을 고려한 반응형 UI
- **사용 방식:** 어린이 중심의 학습 경험과 보호자의 안전·개인정보 고려

## ✨ 주요 기능

### 1. 동요·애니메이션 기반 학습

- 일본어 학습 콘텐츠와 주제별 학습 목록 제공
- 콘텐츠에서 다룰 핵심 단어를 보여 주고 단어 학습으로 연결
- 사용 권한을 확인한 콘텐츠 또는 자체 제작 콘텐츠 활용

**MVP 범위:** 동물·음식 등 2개 주제, 주제별 핵심 단어 3~5개부터 시작합니다.

### 2. 그림·발음·문자 기반 단어 학습

- 단어에 해당하는 이미지 표시
- 일본어 표기와 한국어 뜻 제공
- 일본어 발음 듣기
- 단어를 활용한 간단한 선택형 퀴즈
- 학습 결과 기록

예시 단어:

| 일본어 | 뜻 | 주제 |
|---|---|---|
| ねこ | 고양이 | 동물 |
| いぬ | 강아지 | 동물 |
| りんご | 사과 | 음식 |
| さかな | 물고기 | 동물 |

### 3. 히라가나 따라쓰기

- 히라가나와 발음 표시
- 획순 안내
- 따라쓰기 및 직접 써 보기
- 학습 완료 기록

**MVP 범위:** 우선 `あ`, `い`, `う`, `え`, `お`를 구현한 뒤 확장합니다.

### 4. AI 캐릭터와 일본어 회화

AI 캐릭터가 어린이의 학습 단계와 현재 학습 주제에 맞는 짧은 일본어 질문을 제시합니다.

예시:

```text
🐰 모모: これは なに？
           (이건 무엇일까?)

🐱 [고양이 그림]

👧 어린이: ねこ！

🐰 모모: そう！すごい！
           (맞아! 정말 잘했어!)
```

- 초급 수준의 짧고 쉬운 문장 사용
- 그림이나 선택지를 활용한 대화 지원
- 오답에도 부정적이지 않은 피드백 제공
- AI 응답을 검증하고 학습 목적에 맞지 않는 출력을 제한

### 5. 포인트 및 나만의 마을

학습 활동을 완료하면 포인트를 얻고, 포인트를 사용해 마을 아이템을 해금합니다.

| 활동 | 예시 포인트 |
|---|---:|
| 단어 학습 완료 | +10 |
| 히라가나 학습 완료 | +10 |
| 퀴즈 완료 | +10 |
| AI 대화 미션 완료 | +20 |

마을에는 집, 나무, 동물, 라멘 가게, 기차역 등 다양한 아이템을 추가할 수 있습니다. 보상은 학습을 돕는 수단으로 사용하며, 과도한 경쟁이나 결제를 유도하는 방식은 지양합니다.

### 6. 개인화 복습 미션

- 단어별 정답 여부와 학습 횟수 기록
- 정답률이 낮거나 오랫동안 복습하지 않은 단어 선정
- 선정한 단어를 바탕으로 AI 복습 질문 생성
- 미션 수행 결과를 다음 학습 추천에 반영

초기에는 규칙 기반 로직으로 복습 대상을 선택하고, LLM은 해당 단어를 연습할 질문·힌트·피드백을 생성하는 데 활용합니다.

## 🤖 AI 활용 방안

AI를 단순한 자유 대화 챗봇으로 사용하는 대신, **학습 수준에 맞는 콘텐츠 생성과 개인화 복습**에 집중합니다.

| 영역 | 활용 방식 |
|---|---|
| AI 캐릭터 대화 | 학습 단계와 주제에 맞는 짧은 일본어 질문·힌트·피드백 생성 |
| 예문 생성 | 학습 중인 단어를 사용한 쉬운 예문 생성 |
| 복습 미션 | 복습 대상 단어를 활용한 질문과 퀴즈 생성 |
| 음성 인식(STT) | 선택 기능으로 어린이 음성을 텍스트로 변환 |
| 음성 합성(TTS) | 일본어 단어와 문장의 발음 제공 |

### 개인화 학습 처리 흐름

1. 학습 활동 결과를 저장합니다.
2. 정답률과 마지막 학습 시점 등을 이용해 복습 대상을 선정합니다.
3. 학습 수준·목표 단어·활동 유형을 LLM에 전달합니다.
4. LLM이 질문·힌트·피드백을 생성합니다.
5. 서버가 응답 형식과 안전성을 검증한 뒤 화면에 제공합니다.
6. 미션 결과를 저장해 다음 추천에 반영합니다.

### 프롬프트 설계 예시

```text
[역할]
너는 어린이를 위한 일본어 학습 캐릭터 모모다.

[학습 조건]
- 학습 단계: 초급
- 학습 주제: 동물
- 목표 단어: さかな
- 활동: 단어 복습

[규칙]
- 짧고 쉬운 일본어를 사용한다.
- 현재 학습 수준을 벗어나는 문법은 피한다.
- 오답에도 따뜻하고 긍정적인 피드백을 제공한다.
- 개인정보를 요구하지 않는다.
- 학습 목적에 맞지 않는 요청에는 안전하게 대응한다.

[응답 형식]
일본어 질문, 한국어 참고 뜻, 정답, 힌트, 긍정적 피드백을 구조화된 데이터로 반환한다.
```

### AI 적용 시 고려사항

- LLM이 생성한 일본어의 정확성을 테스트합니다.
- 모델 응답만으로 정답이나 포인트를 확정하지 않습니다.
- 포인트 지급과 학습 완료 판정은 서버의 검증 로직으로 처리합니다.
- API 키는 서버에서 관리하고 클라이언트에 노출하지 않습니다.
- AI 응답이 실패하면 미리 준비한 질문과 안내 문구를 제공합니다.

## 🏗 시스템 아키텍처

```text
┌─────────────────────────────────────┐
│            Web Frontend             │
│ React + TypeScript                  │
│ 홈 / 콘텐츠 / 단어 / 문자 / AI 대화 │
│ 마을 / 학습 결과                    │
└──────────────────┬──────────────────┘
                   │ HTTPS / REST API
                   ▼
┌─────────────────────────────────────┐
│              Backend                │
│ Spring Boot                         │
│ 사용자·학습 기록·미션·보상 관리     │
│ 개인화 로직 및 AI API 연동          │
└──────────────┬───────────┬──────────┘
               │           │
               ▼           ▼
┌────────────────────┐  ┌─────────────────────┐
│      MySQL         │  │     AI Services     │
│ 사용자 및 프로필   │  │ LLM API             │
│ 단어 및 콘텐츠     │  │ STT API (선택)      │
│ 학습 기록          │  │ TTS API             │
│ 포인트 및 아이템   │  └─────────────────────┘
└────────────────────┘
```

### 주요 구성요소

- **Frontend:** 어린이가 사용하는 화면과 상호작용 구현
- **Backend:** API 제공, 학습 기록 저장, 복습 대상 선정, 보상 검증
- **Database:** 사용자 프로필, 단어, 콘텐츠, 학습 기록, 포인트 및 아이템 저장
- **LLM API:** 수준별 대화와 복습 콘텐츠 생성
- **STT/TTS:** 음성 인식과 일본어 발음 제공. MVP 범위와 API 비용에 따라 적용

## 🗃 데이터베이스 설계 초안

| 테이블 | 주요 필드 예시 | 용도 |
|---|---|---|
| `users` | `id`, `email`, `created_at` | 보호자 계정 등 사용자 정보 |
| `children` | `id`, `user_id`, `learning_level` | 어린이 학습 프로필 |
| `words` | `id`, `japanese`, `meaning_ko`, `topic` | 학습 단어 |
| `contents` | `id`, `title`, `topic`, `asset_url` | 학습 콘텐츠 |
| `learning_records` | `id`, `child_id`, `word_id`, `is_correct`, `created_at` | 학습 결과 |
| `conversations` | `id`, `child_id`, `role`, `message`, `created_at` | AI 대화 기록(필요 최소한) |
| `missions` | `id`, `child_id`, `word_id`, `mission_type` | 학습 미션 |
| `rewards` | `id`, `child_id`, `points`, `reason`, `created_at` | 포인트 지급·사용 내역 |
| `village_items` | `id`, `name`, `cost`, `asset_url` | 마을 아이템 정보 |
| `child_village_items` | `child_id`, `item_id`, `unlocked_at` | 아이별 해금 아이템 |

위 표는 설계 초안입니다. 실제 구현 전에는 테이블 관계, 기본키·외래키, 인덱스, 데이터 보유 기간을 ERD와 함께 확정합니다. 어린이의 민감한 정보는 수집하지 않으며, 음성 원본 등은 꼭 필요한 경우가 아니면 저장하지 않습니다.

## ▶ 실행 방법

> 현재는 프로젝트 구조와 기술 구성을 계획한 단계이므로, 아래 명령은 해당 구조로 구현한 뒤 사용하는 예시입니다. 실제 실행 명령은 프로젝트 설정에 맞춰 업데이트합니다.

### 사전 준비

- Node.js 및 npm
- Java 및 Gradle
- MySQL
- 사용할 LLM/TTS API 계정(해당 기능을 구현하는 경우)

### 1. 저장소 복제

```bash
git clone <PUBLIC_GITHUB_REPOSITORY_URL>
cd kotoba-mori
```

`<PUBLIC_GITHUB_REPOSITORY_URL>`을 실제 GitHub 저장소 주소로 바꿔 주세요.

### 2. 환경 변수 설정

`.env.example`을 참고해 로컬 환경 변수를 설정합니다. 비밀 키가 포함된 실제 `.env` 파일은 GitHub에 올리지 않습니다.

### 3. 백엔드 실행

실제 Spring Boot 프로젝트 설정에 맞게 실행합니다. Gradle Wrapper를 사용하는 경우 예시는 다음과 같습니다.

```bash
cd backend
./gradlew bootRun
```

Windows에서는 다음 명령을 사용할 수 있습니다.

```powershell
.\gradlew.bat bootRun
```

### 4. 프론트엔드 실행

```bash
cd frontend
npm install
npm run dev
```

> 위 명령은 일반적인 예시입니다. 프로젝트가 생성되면 `package.json`, Gradle 설정, 포트 및 DB 설정에 맞춰 실행 방법을 확정합니다.

## 🔐 환경 변수 설정

`.env.example` 또는 백엔드의 환경 설정 예시는 다음과 같습니다. 실제 키와 비밀번호를 넣지 말고 변수명만 저장소에 공유합니다.

```dotenv
# Database
DB_HOST=localhost
DB_PORT=3306
DB_NAME=kotoba_mori
DB_USERNAME=your_db_username
DB_PASSWORD=your_db_password

# LLM provider
LLM_API_KEY=replace_with_your_key
LLM_MODEL=replace_with_model_name

# Optional speech services
STT_API_KEY=replace_with_your_key
TTS_API_KEY=replace_with_your_key
```

실제 API 공급자에 따라 변수명과 설정 방법이 달라질 수 있습니다. 백엔드에서는 환경 변수를 읽어 API를 호출하고, 브라우저 코드에 비밀 키를 포함하지 않습니다.

## 🗓 개발 일정

예상 개발 기간은 8주이며, 팀 규모와 개발 환경에 따라 조정합니다.

| 주차 | 단계 | 주요 작업 | 산출물 |
|---|---|---|---|
| 1주차 | 기획 | 요구사항, 타깃, MVP 확정 | 프로젝트 기획서 |
| 2주차 | 설계 | 시스템 구조, ERD, API, 와이어프레임 | 설계 문서 |
| 3주차 | 구현 | 홈, 콘텐츠 목록, 단어 학습 | 기본 학습 기능 |
| 4주차 | 구현 | 히라가나, 포인트, 마을 | 문자·보상 기능 |
| 5주차 | 구현 | LLM 연동, AI 캐릭터 대화 | AI 대화 기능 |
| 6주차 | 구현 | 개인화 복습, 음성 기능 검토 | 개인화 기능 |
| 7주차 | 테스트 | 통합·기능·AI 응답 테스트 | 테스트 결과서 |

### 작업 완료 기준

각 작업은 구현 여부만이 아니라 확인 가능한 완료 조건을 기준으로 종료합니다. 예를 들어 AI 대화 기능은 정상 응답 표시, 오류 시 대체 안내, 응답 검증, 주요 테스트 통과를 완료 조건으로 삼습니다.

## 🧪 테스트 계획

### 기능 테스트

- 콘텐츠 목록과 단어 학습 화면이 정상적으로 표시되는지 확인
- 일본어 단어·뜻·이미지·발음의 연결이 올바른지 확인
- 히라가나와 획순이 올바르게 표시되는지 확인
- 학습 기록이 DB에 저장되는지 확인
- 학습 보상이 중복 지급되지 않는지 확인
- 마을 아이템 해금 결과가 정상적으로 저장되는지 확인
- 복습 대상에 맞는 미션이 생성되는지 확인

### AI 응답 테스트

- 일본어 문법과 의미가 정확한가?
- 현재 학습 수준에 맞는 길이와 난이도인가?
- 목표 단어를 실제로 연습할 수 있는가?
- 오답에 긍정적인 피드백을 제공하는가?
- 부적절한 응답이나 개인정보 요청을 제한하는가?
- API 오류 또는 지연 시 대체 안내가 제공되는가?

### 사용자 경험 테스트

대표 테스트 시나리오:

> 콘텐츠에서 단어를 학습하고, 히라가나를 연습한 뒤, AI 캐릭터의 질문에 답해 포인트를 얻고 마을 아이템을 해금합니다.

테스트 결과는 예상 결과, 실제 결과, 성공 여부, 개선 사항을 기록합니다. 실제 테스트를 수행하기 전에는 테스트 완료로 표시하지 않습니다.

## 🛡 개인정보 및 안전 고려사항

어린이 대상 서비스이므로 개인정보 보호와 AI 안전성을 기능 설계 초기부터 고려합니다.

- 어린이의 실명, 주소, 연락처 등 불필요한 개인정보를 요구하지 않습니다.
- 보호자 동의 및 관련 법령을 고려해 계정과 데이터 처리 방식을 설계합니다.
- 음성 데이터는 필요한 범위에서만 처리하고, 원본 저장은 최소화합니다.
- 대화 데이터의 수집 목적, 보유 기간, 삭제 방법을 정의합니다.
- LLM 응답을 검증하고 부적절한 콘텐츠가 노출되지 않도록 제한합니다.
- 포인트와 보상은 학습을 지원하는 수단으로 설계합니다.
- 콘텐츠·이미지·음원의 저작권과 이용 허가를 확인합니다.
- API 키, 비밀번호, 개인정보가 GitHub에 포함되지 않도록 관리합니다.
